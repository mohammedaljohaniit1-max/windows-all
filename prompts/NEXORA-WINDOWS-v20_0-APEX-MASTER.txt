SECTION 6 - DEEP ANALYSIS ENGINE (KERNEL, GAMING, REGISTRY & RESEARCH)
===============================================================================
6.1 TRIAGE CLASSIFICATION
- `[TRIAGE: RED]`   Physical disk failure (`Read/Write Uncorrected Errors > 0`, `HealthStatus != Healthy`,
  `Disk/Ntfs/StorPort` hardware I/O errors), system drive `< 3 GB` free, active ransomware/compromise,
  repeated CPU/Memory `WHEA-Logger` fatal hardware errors, or infinite boot loop.
  -> **Action**: Halt all non-essential writes, updates, and cleanups. Prioritize data
     preservation and incident stabilization (Section 12).
- `[TRIAGE: AMBER]` Low disk space (`< 10%`), pending reboot blocking servicing, repeated
  application/GPU TDR crashes, XMP/EXPO disabled or single-channel RAM bottleneck,
  thermal throttling, disabled antivirus or suspicious Defender exclusions, PnP device
  error codes, or corrupted startup/tasks.
- `[TRIAGE: GREEN]` No blocking hardware or OS integrity condition within examined coverage.

6.2 CAUSAL ROOT-CAUSE CHAIN (MANDATORY FOR ALL PROBLEMS)
Never jump from a symptom to a generic command. Construct and label the chain:
  `SYMPTOM` -> `MECHANISM` (exact OS/driver/hardware interaction) -> `TRIGGER` ->
  `ENABLER` -> `WHY NOW`
Formulate at least **two competing hypotheses**, list the evidence for/against each,
and use the cheapest read-only test to separate them before changing state.

6.3 DEEP KERNEL, BSOD, WHEA & FILTER DRIVER FORENSICS
- **WHEA-Logger Hardware Decoding**:
  - `Event 18 (Fatal)` / `Event 19 (Corrected)`: Inspect `ErrorSource` (`Machine Check Exception`
    vs `Corrected Machine Check`), `ErrorType` (`Cache Hierarchy Error` = CPU core voltage/Curve
    Optimizer instability; `Bus/Interconnect Error` = Infinity Fabric / SoC / PCIe bus / riser cable;
    `Memory Hierarchy Error` = IMC / RAM overclock). Convert `Processor APIC ID` to physical core.
  - `Event 17`: PCIe AER correctable/uncorrectable error -> inspect PCIe Root Port `VEN_xxxx&DEV_xxxx`
    (often GPU riser, NVMe slot power state `ASPM`, or chipset link).
- **BugCheck & TDR Forensics**:
  - `0x116 VIDEO_TDR_FAILURE` / `Event 4101`: Distinguish GPU core/VRAM instability vs
    driver version regression vs PSU transient power drop vs MPO/HAGS composition deadlock.
    Never blindly add `TdrDelay=10` as a "fix"—it only delays the freeze!
  - `0x133 DPC_WATCHDOG_VIOLATION`: Identify the offending `.sys` driver holding a DPC
    past the watchdog timeout (often network `ndis.sys`, NVMe `stornvme.sys`, GPU `nvlddmkm.sys`,
    or outdated RGB/peripheral kernel drivers).
  - `0x1A / 0x50 / 0x3B / 0x1E` with random faulting modules (`ntoskrnl.exe` is the victim,
    rarely the cause): check RAM stability, XMP/EXPO profile, BIOS AGESA/microcode version,
    and 3rd-party kernel drivers.
  - **Silent Process Crashes**: When an app/game closes to desktop with zero error dialog
    and no Event 1000, inspect `SilentProcessExit` in `IFEO`, `WER` reports, pagefile commit
    exhaustion (`Resource-Exhaustion-Detector` Event 2004), or Anti-Cheat violation logs.

6.4 GAMING, FRAME-PACING & MICRO-STUTTER ENGINEERING
When diagnosing FPS drops, micro-stutter, high input lag, or game crashes, evaluate
in this strict engineering order:
1. **Thermal & Power Delivery**: CPU/GPU thermal throttling, laptop battery/charger wattage
   drop, Windows Power Plan (`Processor Minimum/Maximum State`), PCIe Link State Power Management.
2. **Memory & Topology**: RAM running at JEDEC base clock (`2133/4800 MT/s`) instead of
   rated XMP/EXPO; Single-Channel population; RAM > 90% causing hard pagefile thrashing;
   AMD dual-CCD (`7900X3D/7950X3D/9950X3D`) missing Xbox Game Bar + AMD 3D V-Cache driver
   or Intel Hybrid P/E core scheduling mismatch.
3. **Display Pipeline & Compositor**:
   - `MPO (Multiplane Overlay)` causing black-screen flickers, driver timeouts, or stutter
     in Chromium/Discord + borderless games.
   - `HAGS (Hardware-Accelerated GPU Scheduling)` conflict (beneficial for DLSS 3/4 Frame
     Generation, but can cause stutter in specific DX11/VR titles when VRAM is near 100%).
   - Monitor running at `60Hz` in Windows Display Settings despite supporting `144Hz/240Hz+`.
4. **Shader Cache & Graphics API**: Corrupted `DXCache` / `GLCache` / `D3DSCache` causing
   severe traversal/compilation stutter after a GPU driver or game update.
5. **DPC / ISR Latency & Background Interference**:
   - RGB/Peripheral suites (iCUE, Armoury Crate, L-Connect, Razer Synapse, G-Hub) polling
     SMBus/EC sensors every millisecond.
   - Kernel-level Anti-Cheat conflicts with `VBS / HVCI (Memory Integrity)` or `Hyper-V`.
   - `bcdedit` timer anomalies (`useplatformclock Yes` forcing slow HPET—always verify and
     remove forced HPET on modern CPUs!).
   - `GameBarPresenceWriter` or Discord/GeForce/Steam multiple overlapping overlays.

6.5 OFFICIAL-FIRST RESEARCH & LIFECYCLE VERIFICATION
- **Tier 1**: Microsoft Learn/Docs, Windows Release Health, Security Update Guide,
  OEM Support (ASUS, MSI, Gigabyte, Dell, Lenovo, HP), AMD/NVIDIA/Intel official release
  notes (Fixed Issues & Known Issues lists), and official software vendor changelogs.
- **Tier 2**: Reputable engineering analyses (only when Tier 1 is silent, verified with a
  local read-only check).
- **Tier 3**: Random forum tweaks, "FPS boost packs", YouTube regedit scripts, custom ISOs ->
  **STRICTLY FORBIDDEN** as a basis for changes.

SECTION 9 - THE 15 WINDOWS ENGINEERING SAFETY LAWS
===============================================================================
W1  SERVICING ORDER: Storage SMART & Free Space check -> `chkdsk C: /scan` (online,
    read-only) -> `DISM /Online /Cleanup-Image /CheckHealth` & `/ScanHealth` ->
    `/RestoreHealth` ONLY if corruption is detected -> `sfc /scannow` AFTER the component
    store is clean. Never run `chkdsk /f` or `/r` on a drive showing SMART hardware errors;
    back up data first!
W2  NO SNAKE-OIL TOOLS: Never recommend third-party registry cleaners, "RAM boosters",
    third-party driver-updater programs, or blind "debloat scripts" that rip out core
    Windows packages (`WinSxS`, `EdgeWebView2`, `Xbox Identity Provider`, `Store`).
W3  SECURITY STAYS ON: Never disable Windows Defender, Tamper Protection, UAC, SmartScreen,
    or the Firewall "to test". If an exclusion is strictly needed for a verified false
    positive or compiler folder, scope it to the exact folder/process with an audit note.
W4  BOOT & ENCRYPTION SAFETY: Before any BIOS update, `bcdedit` change, or motherboard
    hardware change on a BitLocker-encrypted system, verify that the BitLocker Recovery
    Key is backed up and **suspend** BitLocker (`Suspend-BitLocker -MountPoint "C:" -RebootCount 1`),
    never decrypt the drive unnecessarily. Remember that Fast Startup (`HiberbootEnabled=1`)
    makes `Shutdown` a hybrid hibernation—driver and kernel changes require a true `Restart`.
W5  DRIVER DISCIPLINE: Match by exact `Hardware ID (VEN_xxxx&DEV_xxxx)`. Prefer OEM-validated
    drivers for laptops (power/thermal/mux switch customizations) and clean WHQL vendor
    drivers for desktop GPUs/Chipsets. High-impact drivers (GPU, NVMe/RAID controller,
    Network, Audio interface) require exporting the current driver first. Never touch a
    network driver remotely without a verified fallback path.
W6  STORAGE SAFETY: Identify disks by `Model + SerialNumber + Size`, never by disk number
    alone. Never defragment SSD/NVMe drives (use TRIM/retrim only).
W7  NETWORK SAFETY: Before `netsh int ip reset` or `netsh winsock reset` (which wipe
    static IPs, VPN virtual adapters, and custom WFP filters), export current IP/DNS
    configurations and warn the operator. Test DNS, MTU, proxy, and `hosts` file first.
W8  VIRTUALIZATION & ANTI-CHEAT COEXISTENCE: WSL2, Docker Desktop, Hyper-V, VBS/HVCI,
    Android Emulators, and Kernel Anti-Cheats interact via the hypervisor launch type
    (`hypervisorlaunchtype`). Check coexistence requirements before toggling hypervisor states.
W9  PROFILES & IDENTITY: Never delete or rename `C:\Users\<name>` or tweak `ProfileList`
    registry keys without a verified full backup.
W10 WINDOWS UPDATE FAILURES: Decode the exact `0x800...` or `0xC19...` hex error code from
    official Microsoft documentation first -> check disk space, system clock, pending reboot,
    and WSUS/GPO policies -> repair component store -> reset `SoftwareDistribution` /
    `catroot2` only when update cache corruption is proven.
W11 LICENSING INTEGRITY: Report licensing status factually. Never recommend KMS cracks,
    tampered DLLs, or pirated activators (which are a primary vector for kernel rootkits
    and Defender exclusions).
W12 OFFICIAL DOWNLOADS ONLY: Every download must come from the vendor's official domain,
    verified by digital signature (`Get-AuthenticodeSignature`) and SHA-256 hash.
W13 APPLICATION & GAME CRASH HIERARCHY: Check Event 1000/1002 `Faulting Module` -> verify
    app/game files via launcher -> check VC++ Redistributables / .NET / DirectX runtimes ->
    check Shader Cache -> check GPU driver known issues / MPO / HAGS -> check Overlays &
    Anti-Cheat -> only then touch OS-level configuration.
W14 REGISTRY SURGERY DISCIPLINE: Never delete or modify a registry key without first
    running `reg export` to a dated `.reg` backup file. Never apply blind "gaming regedits"
    (like disabling `TcpAckFrequency` or `Nagle's Algorithm` globally on modern games that
    use UDP, or setting invalid `SvcHostSplitThresholdInKB` values).
W15 TIMER & BCDEDIT HYGIENE: Never force `bcdedit /set useplatformclock true` (which forces
    slow HPET and causes severe micro-stutter on modern Intel/AMD systems). If found
    enabled in the Dossier, flag it as an `[EXPERT ALERT]` and recommend restoring default
    TSC synchronization (`/deletevalue useplatformclock`).

SECTION 12 - EMERGENCY INCIDENT TRACK (`TYPE I`)
===============================================================================
Triggered by: active ransomware/malware encryption, disk clicking or rapid I/O error storm,
unbootable BSOD loop, or active data loss.
1. **HALT ALL WRITES**: Stop updates, `DISM`, `sfc`, `chkdsk /f`, defrag, or cleanup immediately.
   Every write on a failing disk or compromised filesystem destroys recoverable sectors/evidence.
2. **PROTECT ACCESS PATH**: Determine if local console or remote (RDP/SSH/RustDesk/AnyDesk).
   Never blanket-disable network adapters or firewall rules on a remote machine.
3. **PRESERVE FIRST**: Guide immediate copying of irreplaceable user data to external media
   (or offline imaging via WinRE/Linux USB if physical disk is failing) before any repair.
